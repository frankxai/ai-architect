# Review gates

A release uses evidence gates, not an average score. Any red gate blocks publication.

| Gate | Pass condition | Current |
|---|---|---|
| scope | governing reader, reader action, non-goals, edition state are explicit | PASS |
| manuscript | every required chapter exists and clears the word floor | PASS |
| claims | every factual claim has a ledger record and supporting source IDs | PASS |
| sources | primary-source bias; volatile sources carry access and review dates | PASS |
| style | Humanizer static gate passes; editor reads opening, transitions, and ending aloud | PASS |
| security | named reviewer checks trust boundary, identity, privilege, and destructive tools | PENDING |
| legal | accountable author confirms that regulatory language is architectural guidance, not legal advice | PENDING |
| rights | Frank confirms whether guide content inherits the repository's Apache-2.0 license or receives a separate content license | PENDING |
| independent verification | fresh-context verifier reopens sources and samples at least 20 claims | PENDING |
| author approval | Frank approves title, positioning, experience claims, and release note | PENDING |
| release | tag, immutable receipt, channel hashes, and distribution links exist | PENDING |

## Verification sample

The independent verifier must sample:

- every legal date and protocol version;
- every price in the model appendix;
- all direct quotes, if any;
- five security claims;
- five evaluation or operations claims;
- five internal prescriptions, checked for internal consistency;
- every outbound link in the release manifest.

The verifier records source URL, observed text, result, and date. “Looks right” is not a result.
