## Decision: bind approval to the action

Before granting an agent another tool, ask where permission is checked after the model produces its proposal. Approval should bind an authenticated actor to a tenant, resource, action, amount, and replay key. A changed proposal needs a new decision. Revocation must be checked at execution time.

This is an application design recommendation, not a new protocol announcement. MCP's authorization requirements inform the trust boundary, but protocol compliance alone does not establish your application's approval and retry policy. The proposed pattern is recorded as C054. ## Test it

Run the [delegated-authority lab](../../labs/delegated-authority/README.md). Add one hostile proposal for a tool you own. The expected result is a denial and unchanged state, followed by an accepted request that cannot execute twice under the same replay key.

The reference implementation is deliberately in-memory. It does not survive a restart or coordinate multiple workers. Porting it into production requires authenticated identities, durable grants and revocation, approved human roles, transaction and reconciliation contracts, and a security review.
