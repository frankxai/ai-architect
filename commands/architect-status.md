# /architect-status

Prints where a run stopped. It dispatches no agent, evaluates no gate, and writes no file.
Argument: `$ARGUMENTS` — `--json` prints the `gates` object verbatim instead of the table.

## Step 1 — read the state

Read `docs/architecture/architecture.json`.

If it does not exist, print this and stop:

```
no run found — docs/architecture/architecture.json is missing. Run /architect "<goal in one sentence>" to start.
```

Read `docs/architecture/WORKFLOW.md` for the stage order. Parse the table under `## Stage table`,
whose columns are `stage | agent | input | output | gate`, and take the stage order from the row
order. If the repository has no `WORKFLOW.md`, use `${CLAUDE_PLUGIN_ROOT}/templates/WORKFLOW.md` and
say that the order came from the template.

## Step 2 — print the gate table

One row per stage, in stage-table order, with the values as they are in the file. Do not re-derive
evidence and do not re-evaluate a gate — that is `/architect-<stage>` and `/architect-verify`. This
command reports state; it does not produce it.

```
architecture: <goal>                       generated_at: <date>

stage      gate              status    verified_by          evidence
frame      gate.frame        PASS      null                 <first pointer>
discover   gate.discovery    PASS      null                 <first pointer>
flow       gate.flow         FAIL      null                 —
decide     gate.decisions    FAIL      null                 —
cost       gate.economics    FAIL      null                 —
secure     gate.trust        FAIL      null                 —
prove      gate.evals        FAIL      null                 —
operate    gate.operate      FAIL      null                 —
verify     gate.verify       FAIL      null                 —
```

A gate absent from the `gates` map prints as `MISSING`, not as `FAIL`: absent and failed are
different facts, and only one of them means a stage ran. A `SKIPPED` gate prints its reason.

## Step 3 — print the decisions and the unowned planes

```
decisions   model=<verdict>  loop=<verdict>  trust=<verdict>  run=<verdict>
unowned     <plane ids whose owner is "unowned", or "none">
```

When more than one decision is `OPEN`, mark the one to fix first in the order `trust`, `run`, `loop`,
`model`.

With `--json`, print the `gates` object from `architecture.json` verbatim instead of steps 2 and 3,
and nothing else, so the output can be piped.

## Write scope

None. This command writes no file, not even `generated_at`.

## Stop conditions

1. `architecture.json` does not parse. Print the parse error and the path, and stop. Do not repair
   the file.
2. `WORKFLOW.md` has no stage table, different columns, or zero rows. Print that the workflow file
   is corrupted and stop; a stage order guessed from memory is how a customer's added stage silently
   disappears.
3. The `gates` map names a gate that no stage row references, or a stage row names a gate that is
   absent from the map. Print both lists and stop.

## Report and stop

After the table, print the last line exactly:

```
next: /architect-<stage of the first incomplete gate> — <agent> → <output files> → <gate id>
```

When every gate is `PASS`, print instead:

```
next: none — every gate is PASS. Receipt: docs/architecture/receipts/<YYYY-MM-DD>-verify.md
```
