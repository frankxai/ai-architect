# /architect-review

A standalone review. It does not run a lifecycle stage, it does not evaluate a gate, and it writes no
files. Use it on a codebase that already exists, before deciding whether the full lifecycle is worth
running. Argument: `$ARGUMENTS` — a path to scope the review, or `--interview` when there is no
codebase to grep.

## Step 1 — load the skill

Invoke the `ai-architect-review` skill and follow it exactly as written: step 1, the four decisions;
step 2, the plane walk; step 3, the symptom-to-plane table; then its output format.

The skill is the rubric. Do not summarise it, reorder it, add checks to it, or substitute your own
judgement for one of its checks. If a check cannot be answered with evidence, the check fails — that
result is the point of running it.

## Step 2 — decide grep or interview

If `$ARGUMENTS` names a path, or the working directory is a repository with source in it, run the
skill against that code. Every verdict then carries a grep result, a file and a line, or a measured
number.

If `$ARGUMENTS` contains `--interview`, or there is no codebase, run the skill's interview mode. Say
plainly in the report that the evidence is testimony rather than grep, and write the plane section
as the skill instructs:

```
### Unowned planes
Not assessed — interview mode, no codebase access.
```

## Step 3 — report in the skill's format

Print the report in the skill's output format and nothing else: the four decisions with verdicts and
evidence, the unowned planes with the symptom each is likely to surface as, and the one change to
fix first. Lead with what is unowned, not with what is fine. Do not assign a score — a number
invites arguing with the number instead of fixing the finding.

## Write scope

None. This command writes no file.

`docs/architecture/review.md` belongs to `independent-verifier` and is written by
`/architect-verify`. If the user wants this report on disk, say that, and offer `/architect` to run
the lifecycle that produces it.

## Stop conditions

1. A verdict would be recorded without evidence of an accepted form — a `path/to/file.ts:L42`
   pointer, a fenced command with its observed output, or a stated measurement.
2. Reading the code would require credentials or access the session does not have. Say which part
   was not assessed rather than assessing it anyway.
3. The user asks for a fix to be applied. This command reviews; it does not edit.

## Report and stop

After the skill's report, print the last line exactly:

```
next: /architect "<goal in one sentence>" — run the gated lifecycle, or /architect-status to see where an existing run stopped
```
