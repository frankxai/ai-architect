# /architect-decide — stage 4 of 9

Dispatches `principal-architect` for the `decide` stage. Argument: `$ARGUMENTS` — `--decision <id>`
re-opens exactly one of the four; `--interview` runs the four checks as an interview because there
is no codebase to grep, and the evidence is then testimony rather than a grep result, which the
agent must say plainly.

The artifact root is `docs/architecture/` relative to the repository root. Never write outside it.

none. SOP.md wins where it disagrees with this file. Say which one you loaded.

## Step 2 — check the gate behind you

Read `docs/architecture/architecture.json`. If `gates["gate.flow"].status` is not `PASS` — or

Also stop if `docs/architecture/01-discovery.md` contains an `[assumed]` tag. Return the run to

decision.

## Step 4 — evaluate gate.decisions yourself

Read `SYSTEM.md`, the ADRs, and `architecture.json`, and check:

- all four decisions are present under the keys `model`, `loop`, `trust`, `run`
- each carries a verdict of exactly `MADE` or `OPEN`
- each carries an evidence pointer of the form `path/to/file.ts:L42`, or a fenced command together
  with its observed output. A verdict with any other kind of evidence is `OPEN`, whatever the row
  says
- every `OPEN` decision carries a non-null `deferral_cost` that names what gets more expensive and
  the date it was measured from
- each of the seven planes `experience`, `observability`, `evaluation`, `orchestration`, `tools`,
  `context`, `model` has a named owner. `unowned` is a recorded state, not a missing one, and it
  carries the symptom the next incident is likely to surface as
- `SYSTEM.md` states the boundary, lists the seven planes with owners, and lists the four decisions
  with verdict and evidence pointer
- one ADR exists for each decision that changed state during this run
- `SYSTEM.md` and each ADR end with the stamp line

Run these and record what you observe:

```

Then re-derive at least one evidence pointer yourself. A verdict you did not check is a verdict the
verifier will check for you later, at a worse moment.

## Step 5 — record the result

`principal-architect` owns `architecture.json` and writes the decisions, planes, and artifacts. This
command sets only `gates["gate.decisions"].status`, `.evidence` from the pointers you re-derived, and
`generated_at`. Leave `verified_by` as `null`.

## Stop conditions

1. A decision would be recorded `MADE` without an evidence pointer of an accepted form.
2. `01-discovery.md` contains an `[assumed]` tag.
3. A plane has no candidate owner and the customer has not been asked. It is recorded `unowned`
   rather than given an invented owner.
4. The work would require editing application source code.
5. `SYSTEM.md`, an ADR, or `architecture.json` already exists, so a `.proposed` variant was written
   beside it.
6. A human gate named in SOP.md is reached.

## Report and stop

Print the gate result, the files written, the four verdicts, and the unowned planes. When more than
one decision is `OPEN`, name the one to fix first in the order `trust`, `run`, `loop`, `model`, and
put that decision id in the line:

```

```

On `PASS`, the last line is exactly:

```
