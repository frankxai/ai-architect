## Buyer and what a team builds with this

An engineering lead, staff engineer, or CTO designing a production agent system uses this playbook and kit to ship a working multi-agent architecture in days: a C4 system/container/component model in Structurizr DSL and Mermaid, 10 worked Architecture Decision Records with concrete rejected options, an OAuth 2.1 audience-bound MCP server with HMAC two-phase approval tokens, a two-provider TypeScript supervisor, and an OpenTelemetry trace cost analyzer that computes cost per accepted outcome from real span exports.

## Where this playbook and kit must win

- **Against books and free vendor guides (*AI Engineering*, Anthropic/OpenAI/OWASP docs):** We turn the concepts into **runnable, modifiable architecture artifacts** that a team drops into their repository on day one: `kit/c4/agentic-system.dsl` (Structurizr C4), `kit/adrs/ADR-0001..0010.md` (worked decisions with concrete rejected alternatives), `kit/mcp/reference-mcp-server.mjs` (working stdio MCP server with OAuth 2.1 RFC 8707 audience checks and HMAC tenant+expiry approval tokens), `kit/workflows/supervisor-maker-checker.ts` (two-provider supervisor with recursion and write-collision guards), and `kit/workbooks/evaluate-workbook.mjs` (which ingests OpenTelemetry GenAI span exports to compute cost per accepted outcome).
- **Against coding-agent config kits (ClaudeKit at USD 99, BuiltByZac at USD 99, GetAutopilotKit at USD 79):** Those packs optimize a developer's coding-agent harness (primarily `.claude/`). This product is an **architecture design and runtime boundary kit** for the production agent system the team is building for its own users, spanning multiple model families (OpenAI, Anthropic, Google, xAI) and cloud runtimes.
