# ADR-0003: Enforce tenant-scoped retrieval and claim-to-source attribution

- **Status:** Accepted
- **Date:** 2026-10-24
- **Pattern:** PAT-03
- **Mitigates:** FM-03

## Context
Multi-tenant RAG indexes and ungrounded synthesis risk leaking another customer's documents or emitting fabricated policy statements as fact.

## Decision
Require a verified `tenantId` extracted from the authenticated session token on every retrieval query, tag each retrieved chunk with its source ID and access date inside `<untrusted-content>`, and drop any generated sentence whose citation marker does not resolve to an retrieved passage (`templates/deploy/answer-core/`).

## Alternatives Considered and Rejected
1. **Filter retrieval results by tenant inside the LLM prompt after fetching from a shared global top-K query:** Rejected because cross-tenant chunks still enter the model context window and can be extracted via prompt injection.
2. **Allow the model to pass `tenantId` as an unverified tool argument:** Rejected because a confused-deputy prompt can supply another tenant's identifier (`E_TENANT_MISMATCH`).
3. **Post-hoc LLM-as-a-judge hallucination scoring without deterministic citation stripping:** Rejected because a probabilistic judge adds latency and token cost while still permitting ungrounded numbers to slip through.

## Consequences
- **Positive:** Eliminates `FM-03` with a deterministic, script-verified control and clear operational trade-offs.
- **Negative / Cost:** Requires maintaining explicit schema contracts, test fixtures, and verification checks in CI.
