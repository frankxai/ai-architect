# ADR-0002: Isolate vendor SDKs behind one canonical capability seam

- **Status:** Accepted
- **Date:** 2026-10-24
- **Pattern:** PAT-02
- **Mitigates:** FM-02

## Context
Model vendors update model weights, deprecate floating aliases, and change tool-call serialization across releases (`S01`, `S02`, `S03`, `S04`).

## Decision
Call language models only through an internal capability router (`fast-classifier`, `balanced-builder`, `frontier-reasoner`, `independent-checker`) that binds each role to a pinned snapshot ID, validates responses against closed JSON schemas, and keeps a tested fallback on a second provider family.

## Alternatives considered and rejected
1. **Import vendor SDK clients directly inside route handlers and domain services:** Rejected because replacing a deprecated model or failing over during a provider outage requires editing dozens of application files under incident pressure.
2. **Bind production workloads to floating aliases such as `-latest`:** Rejected because silent upstream snapshot swaps change structured output formatting and token verbosity without triggering a deployment review.
3. **Normalize every model call to unvalidated plain-text chat completions:** Rejected because downstream workflow steps require typed JSON fields and deterministic error codes (`E_SCHEMA_DRIFT`) when a model omits a required key.

## Consequences
- **Positive:** Isolates application business logic from vendor SDK churn and blocks malformed structured outputs at the gateway boundary (`E_SCHEMA_DRIFT`).
- **Negative:** Requires maintaining normalized request/response adapters and `required_output_keys` contracts (`kit/prompts/prompt-set.json`) for every prompt role.
- **Neutral:** Shifts model selection from hardcoded vendor strings to four capability tiers (`tier-a-fast-classifier` through `tier-d-independent-checker`).
