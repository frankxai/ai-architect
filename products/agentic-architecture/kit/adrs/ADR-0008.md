# ADR-0008: Block deployment on deterministic contract and adversarial eval suites

- **Status:** Accepted
- **Date:** 2026-10-24
- **Pattern:** PAT-08
- **Mitigates:** FM-08

## Context
Edits to system prompts, skills, or model snapshots can silently break output schemas, refusal rules, or prompt-injection defenses while passing casual manual spot-checks (`S13`, `S14`).

## Decision
Require every prompt and skill in `kit/prompts/prompt-set.json` and `evals/cases/` to define and pass three deterministic evaluation case classes (`golden` capability invariants, `refusal` boundaries, and `injection` probes) before merge.

## Alternatives considered and rejected
1. **Manual interactive testing in a chat UI before merging prompt changes:** Rejected because manual checks are unrepeatable and rarely re-test adversarial injection or refusal edge cases.
2. **Testing only happy-path `golden` examples without `refusal` or `injection` cases:** Rejected because an overly compliant prompt can score 100% on golden tasks while failing every boundary probe.
3. **Running live LLM-graded evaluations on every commit without deterministic fixture gates:** Rejected because non-deterministic grader variance causes flaky CI and hides hard schema regressions.

## Consequences
- **Positive:** Catches refusal regressions and prompt-injection bypasses deterministically in under two seconds on every pull request.
- **Negative:** Requires authoring and maintaining a balanced triad (`golden`, `refusal`, `injection`) whenever a prompt or skill is added.
- **Neutral:** Separates fast deterministic PR contract checks (`npm run evals`) from slower live-model canary benchmarks.

## Verification command
`npm run evals`
