# ADR-0006: Design idempotent saga transitions for long-running agent jobs

- **Status:** Accepted
- **Date:** 2026-10-24
- **Pattern:** PAT-06
- **Mitigates:** FM-06

## Context
Asynchronous agent workers and webhook consumers experience mid-transaction crashes, network retries, and out-of-order events such as a refund arriving before payment confirmation.

## Decision
Execute idempotent state upserts before recording the event ID as processed (`write-before-mark`), write a terminal refunded tombstone (`paidAt: null, status: 'refunded'`) when a cancellation arrives first so a delayed grant cannot re-activate access, and require `idempotencyKey` on all Tier 1/2 mutations.

## Alternatives Considered and Rejected
1. **Mark `event.id` processed at the start of the webhook handler before state writes complete:** Rejected because a transient database error after marking causes the upstream retry to return `duplicate` and permanently drop the customer's entitlement.
2. **Reject out-of-order refund webhooks with HTTP 422 when the payment record is not yet present:** Rejected because the subsequent delayed payment webhook will succeed and grant active access to a refunded order.
3. **Overwrite existing order records when a merchant reuses an order ID with different buyer parameters:** Rejected because silent overwrites corrupt financial reconciliation instead of raising `409 E_ORDER_CONFLICT`.

## Consequences
- **Positive:** Eliminates `FM-06` with a deterministic, script-verified control and clear operational trade-offs.
- **Negative / Cost:** Requires maintaining explicit schema contracts, test fixtures, and verification checks in CI.
