# ADR-0007: Bound token, retry, and human-review cost per accepted outcome

- **Status:** Accepted
- **Date:** 2026-10-24
- **Pattern:** PAT-07
- **Mitigates:** FM-07

## Context
Rolling context compaction erases negative constraints during long runs, and retry loops on large prompts inflate actual compute cost far beyond first-pass token estimates.

## Decision
Store standing constraints and checklists in a verbatim working document outside compacted chat history, enforce a 70% soft stop and 80% hard stop (`E_BUDGET_EXCEEDED`), and compute unit economics from OpenTelemetry GenAI span exports (`ingestOtelTraceSpans` in `kit/workbooks/evaluate-workbook.mjs`) divided by accepted outcomes.

## Alternatives considered and rejected
1. **Rely on automatic chat transcript summarization to preserve run constraints:** Rejected because lossy summarization drops exact commit SHAs, dollar caps, and 'do not touch' boundaries across compactions.
2. **Price agent workflows using single-call happy-path input/output token counts:** Rejected because a 1.4x mean retry rate and 8 minutes of human review per run frequently dominate total unit cost.
3. **Allow unbounded automatic retries on tool or validation failures:** Rejected because 5 retries with a growing 200k-token context window can multiply a USD 0.15 task into USD 4.50 before failing (example only — check current pricing).

## Consequences
- **Positive:** Protects session invariants from context compaction and halts runaway retry loops at 80% of the per-run budget (`E_BUDGET_EXCEEDED`).
- **Negative:** Requires maintaining a separate structured working document per session and modeling p95 retry multipliers before launching new workloads.
- **Neutral:** Shifts unit-economics reporting from single-call list token prices to all-attempts cost per accepted outcome (`kit/workbooks/evaluate-workbook.mjs`).
