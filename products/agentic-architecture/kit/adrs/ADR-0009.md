# ADR-0009: Record reconstructable run receipts without leaking customer secrets

- **Status:** Accepted
- **Date:** 2026-10-24
- **Pattern:** PAT-09
- **Mitigates:** FM-09

## Context
Debugging multi-step agent failures requires span-level visibility into model and tool calls (`S16`), but logging raw headers or payloads leaks bearer tokens and customer PII.

## Decision
Emit OpenTelemetry GenAI spans (`gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `tool.cost_usd`, `run.accepted`) through a deterministic redaction filter that strips secrets and PII, and feed exported span JSON directly into `ingestOtelTraceSpans`.

## Alternatives considered and rejected
1. **Log full `Request` and `Response` bodies to stdout on webhook or tool errors:** Rejected because raw payloads contain `Authorization` headers, webhook signatures, and customer email addresses.
2. **Disable tracing in production to avoid PII compliance risk:** Rejected because operators cannot diagnose retry loops, latency bottlenecks, or cost spikes without span-level token and status attributes.
3. **Adopt a proprietary observability agent that requires routing all prompts through a third-party proxy:** Rejected because it introduces an external single point of failure and data-residency exposure.

## Consequences
- **Positive:** Prevents raw bearer tokens and customer PII from leaking into observability backends while enabling exact cost-per-accepted-run reconciliation from spans.
- **Negative:** Requires instrumenting every model and tool call with `runId`, `attempt`, `accepted`, and token usage attributes.
- **Neutral:** Connects OpenTelemetry GenAI trace exports (`sample-otel-spans.json`) directly to the financial workbook (`ingestOtelTraceSpans`).
