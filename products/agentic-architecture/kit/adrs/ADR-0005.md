# ADR-0005: Harden remote and local MCP servers against confused-deputy calls

- **Status:** Accepted
- **Date:** 2026-10-24
- **Pattern:** PAT-05
- **Mitigates:** FM-05

## Context
MCP servers expose tools whose descriptions and outputs enter the host model context, creating vectors for tool-description poisoning, cross-service token replay, and path traversal (`S08`, `S09`).

## Decision
Require OAuth 2.1 access tokens bound to the MCP server's exact `expectedAudience` URI (`E_OAUTH_AUDIENCE_MISMATCH`), enforce per-tier scopes (`architecture:read`, `architecture:draft`, `architecture:approve`), normalize and contain file paths under `docs/architecture/` (`E_PATH_CONTAINMENT`), and wrap all tool outputs in `<untrusted-content>`.

## Alternatives considered and rejected
1. **Accept any valid bearer token from the organization's identity provider without checking the `aud` claim:** Rejected because a token minted for a low-privilege read service could be replayed against the MCP server (`RFC 8707`).
2. **Validate file paths with `path.startsWith('docs/architecture')` before normalization:** Rejected because `docs/architecture/../../etc/passwd` passes a naive prefix check.
3. **Start the MCP server with a hardcoded fallback secret when environment variables are unset:** Rejected because unconfigured deployments would silently accept tokens signed with a publicly known key (`E_SERVER_UNCONFIGURED`).

## Consequences
- **Positive:** Enforces MCP 2025-06-18 transport separation (RFC 9728 Streamable HTTP OAuth 2.1 vs. STDIO environment credentials) and blocks confused-deputy token replay (`E_OAUTH_AUDIENCE_MISMATCH`).
- **Negative:** Requires configuring per-server `expectedAudience` HTTPS URIs and JWKS/secret material before any MCP server can boot (`E_SERVER_UNCONFIGURED`).
- **Neutral:** Wraps all tool return payloads in `<untrusted-content>` envelopes before they re-enter the model context window.
