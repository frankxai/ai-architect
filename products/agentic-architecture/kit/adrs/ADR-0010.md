# ADR-0010: Enforce clean-room archive verification and 48-hour provider exit drills

- **Status:** Accepted
- **Date:** 2026-10-24
- **Pattern:** PAT-10
- **Mitigates:** FM-10

## Context
Teams often validate builds only inside their monorepo git checkout and hardcode vendor-specific storage or model APIs that prevent exiting a provider when terms or prices change.

## Decision
Verify every release package by extracting the built archive into an isolated `/tmp` directory outside git and running cold verification, and maintain a tested 48-hour exit runbook that swaps model providers via the capability seam (`PAT-02`) and exports all state, ADRs, and C4 models in open formats.

## Alternatives Considered and Rejected
1. **Run test suites only inside the authoring git repository checkout:** Rejected because tests that accidentally read unshipped internal files pass in git but fail with `ENOENT` for the buyer who unzips the release archive.
2. **Store architecture diagrams and decision records only inside a proprietary SaaS wiki or diagramming tool:** Rejected because diagrams cannot be diffed in pull requests or validated by CI scripts.
3. **Open live checkout before running a clean-room buyer simulation and test-mode payment/refund rehearsal:** Rejected because broken delivery links or refund races destroy buyer trust on launch day.

## Consequences
- **Positive:** Eliminates `FM-10` with a deterministic, script-verified control and clear operational trade-offs.
- **Negative / Cost:** Requires maintaining explicit schema contracts, test fixtures, and verification checks in CI.
